# Transactional Email: Typed, Localized Templates

## Goal

Add repository-owned transactional email templates that are independently testable, easy to redesign, localized in English and German, and render both HTML and plain text.

## Depends On

- `tasks/001-transactional-email-transport.md` for the provider-neutral message contract.

## Scope

- Create `src/lib/server/email/templates/`.
- Add a shared email layout/branding helper with conservative, email-client-safe inline CSS.
- Add typed template renderers for:
  - welcome
  - email verification
  - password reset
  - email address change confirmation
- Each renderer must accept only the data it needs, including an explicit supported locale and action URL where relevant.
- Each renderer must return `{ subject, html, text }` compatible with the transport message contract.
- Add all email copy to `messages/en.json` and `messages/de.json`. Do not edit generated `src/lib/paraglide/` files.
- Render template copy using the explicit locale passed to the template. Do not depend on a SvelteKit request or global locale state because delivery may later run in a worker.

## Constraints

- Do not use Svelte components as email templates.
- Do not add provider calls, Better Auth callbacks, routes, or queues in this issue.
- Use semantic, table-based layout only where required for broad email-client compatibility; keep design logic centralized in the shared layout.
- Escape/interpolate dynamic user-provided content safely. Action URLs must be generated by trusted server code and rendered as escaped attribute values.
- Keep a usable plain-text version for every template; it must include the action URL where applicable.
- Do not duplicate message copy in template source files when it belongs in Paraglide messages.

## Acceptance Criteria

- Each template has a typed input and returns subject, HTML, and text.
- English and German renders use the correct localized copy.
- Every action email contains the exact trusted action URL in HTML and text output.
- Rendered HTML has a complete document structure and no Svelte/browser-only dependencies.
- Tests cover every template in both locales, dynamic escaping, and plain-text fallback content.

## Verification

Run `bun run test -- --project server`, `bun run check`, and `bun run lint`.
